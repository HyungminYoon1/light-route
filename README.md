# LIGHT ROUTE — 빛의 미궁

현재 변경은 로컬 구현입니다. 브라우저·공개 배포 상태는 [검증 기록](docs/verification.md)에 구분합니다.

[사이트 열기](https://hyungminyoon1.github.io/light-route/)

8×8 격자에서 거울·분기·색 변환기를 조작하는 6개 장, 18단계 퍼즐입니다. 목표와 필수 경유지를 모두 켜면서 금지 센서는 피해야 합니다. 기존 어려운 light-v2 캠페인·같은 코드의 배치를 유지합니다.

- 기본 연습과 선택형 제한 이동. 합법 완료 경로로 단계별 이동 예산을 검증합니다.
- 최근 코드 선택, 새 세트, 마지막 진행 이어하기, 기록 모두 삭제.
- 연습/제한 이동과 스스로 완료/힌트 사용 최고를 각각 표시합니다.
- 회전·되돌리기·힌트, A/C 문자, 고정 거울, 좌표와 텍스트 광선 경로.
- Tab/Enter/Space와 같은 행·열 화살표 이동. 작은 화면의 단계·도구 버튼 최소 높이 44px.

| 장 | 단계 | 도전 조건 |
| --- | --- | --- |
| 반사의 설계 | 1–3 | 4회 이상의 방향 전환, 긴 우회와 방해 거울 |
| 필수 경유지 | 4–6 | 빛을 멈추지 않는 체크포인트 2–3개도 통과 |
| 분기 회로 | 7–9 | 직진·반사 빛으로 2–3개 목표를 동시에 연결 |
| 색의 순서 | 10–12 | 목표와 경유지마다 A/C를 맞추는 변환 순서 |
| 안전한 빛 | 13–15 | 세 목표, 네 경유지, 금지 센서 회피 |
| 마스터 회로 | 16–18 | 네 목표와 모든 제약의 결합, 17–18단계의 고정 거울 |

## 규칙과 저장 범위

기본 1,000점에서 조작 1회마다 15점, 힌트 1회마다 120점 차감하고 최소 20점입니다. 되돌리기도 조작입니다. 처음 배치는 조작·힌트를 초기화하고 새 시도를 시작합니다. 힌트는 방해 장치와 고정 거울을 제외한 검증된 해답으로 안내하며 다른 유효한 해답도 인정합니다. 한 번이라도 힌트를 사용하면 해당 시도는 힌트 기록에만 들어갑니다.

제한 이동 예산은 초기 배치의 실제 합법 회전 완료 경로 길이 + max(1,floor(길이/5))입니다. 마지막 허용 조작으로 완료하면 성공, 미완료 상태에서 한도를 채우면 종료됩니다. 힌트는 이동 예산을 소비하지 않으며 점수와 기록 구분에 반영합니다. 연습에는 이동 한도가 없지만 저장 입력은 한 판에 최대 1,024개이며 한도에 도달하면 처음 배치로 새 시도를 시작해야 합니다. 최소 이동 수를 증명하는 모드는 아닙니다.

목표·벽·금지 센서는 광선을 멈춥니다. 경유지는 해당 색이 통과해야 하며 색 지정이 없으면 어느 색도 허용합니다. 목표를 모두 켜도 경유지를 놓치거나 금지 센서를 켜면 완료되지 않습니다. 광선은 칸×방향×색의 512개 상태 안에서 처리하며 분기 합류와 실제 순환을 구분합니다.

light-route-session-v1에 최근 코드 12개(마지막 선택 단계·방식), 마지막 진행 1개, 완료 최고 기록 120개를 최대 512KiB로 저장합니다. 크기를 넘으면 오래된 완료 기록부터 제거합니다. 저장 항목은 light-v2/light-run-v1/코드/단계/방식/힌트 여부로 구분합니다. 복원 시 초기 배치를 다시 생성하고 회전·되돌리기·힌트를 재실행해 모든 장치 방향·조작·힌트 수를 대조합니다. 최근 256회 회전은 이어하기 후에도 되돌릴 수 있습니다.

새로 방문했을 때 마지막 기록이 있으면 이어하기를 선택합니다. 코드 시작·최근 코드·단계·방식 선택은 해당 단계의 처음 배치에서 시작하며 마지막 진행 슬롯을 교체합니다. 초기 조회나 이어하기에는 저장하지 않습니다. 기존 light-route-v1의 최고와 진행은 원래 영역에 유지하며 힌트 여부 미기록으로 따로 표시합니다. 새 독립 완료로 임의 이전하지 않습니다. 기록 모두 삭제는 이전 버전 기록도 포함하며 삭제 직후 빈 진행을 다시 저장하지 않습니다.

## 실행과 배포

Node.js 22 이상, 런타임 외부 의존성 없음.

```sh
npm run dev -- 0
npm test
npm run check
```

개발 서버는 loopback에서 `dist/`만 제공합니다. `main`에 푸시하면 고정 SHA Actions가 시험·정적 검사 후 `dist/`를 GitHub Pages에 배포합니다. 저장소 Pages의 배포 소스는 GitHub Actions입니다.

## 기록과 개인정보

기록은 이 브라우저에만 저장하며 삭제할 수 있습니다. 외부 전송·계정·공개 랭킹은 없습니다. CSP connect-src none을 유지합니다.

갤러리용 web-lab-progress-v1에는 15개 허용 서비스 ID별 completed/total/updatedAt만 공유합니다. 이 앱은 저장에 성공한 힌트 없는 실제 완료에서 보관 중인 서로 다른 단계 수(최대18)를 재계산합니다. 코드·조작 내역·개인정보는 공유하지 않습니다. 초기 화면·방문·힌트·예시는 완료로 집계하지 않습니다. 자체 기록 삭제는 다른 앱 요약을 보존합니다. 요약 크기는 최대8KiB, 시각은 실제 갱신 때의 기기 시각입니다. 브라우저의 기기 내 집계이며 서버 인증 기록이 아닙니다.

공유 요약에 알 수 없는 필드·앱 ID, 손상된 항목·JSON, 빈 문자열 또는 상한 초과 내용이 있으면 원문을 그대로 보존하고 요약 갱신·자기 항목 삭제를 중단합니다. 임의 정리나 자동 복구는 하지 않습니다. 이때도 퍼즐 플레이와 자체 기록 저장·삭제는 별도로 동작하며 요약 실패를 화면에 알립니다. 키 자체가 없는 경우와 정상적인 빈 apps 객체는 허용합니다. 삭제할 자기 요약이 이미 없으면 공유 내용을 다시 쓰지 않습니다.
