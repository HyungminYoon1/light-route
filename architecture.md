# LIGHT ROUTE architecture

Browser-only static GitHub Pages application. Public output is dist/ only.

- dist/src/model.js (or questions.js): pure deterministic generation, validation, rules and scoring. No DOM/storage/network.
- dist/src/app.js: DOM rendering, inputs and session lifecycle. Uses model functions; no DB or remote calls.
- dist/src/core.js: seeded RNG, bounded input validation, feature-detected WebMCP, device-local storage helpers.
- dist/src/session.js: pure deterministic run reducer, legal limited-move witness, replay/snapshot validation, retention and independent-completion aggregation. No DOM, storage or network. Existing light-v2 generator/layouts remain unchanged; new run rules are light-run-v1.
- dist/src/storage.js: bounded device-local session IO. Session key light-route-session-v1 contains schema/version/rulesVersion, at most 12 recent codes, one last replay, and 120 completed best replays; total UTF-8 payload <=512KiB, evicting oldest best records first. Each replay is <=1,024 actual rotate/undo/hint actions; undo is the latest 256 rotations. Restore regenerates the board, legally replays every action, and matches all orientations/move/hint counters. No client score field is trusted.
- dist/src/progress.js: minimal shared device-local gallery summary only, key web-lab-progress-v1. Shape {version:1,apps:{repoId:{completed,total,updatedAt}}}; 15 explicit service IDs, <=8KiB, integer 0..total<=1,000, canonical ISO UTC date from the actual update time. Own total is 18, completed is unique stage count among retained, replay-validated, hint-free completions across practice/limited. Write only after a durable actual independent completion, or reconcile retention on a later actual completion. Never write on initial view, restore, hint, stage visit or example. No code/actions/identity/file payload in the aggregate. Read-modify-write preserves valid other service aggregates; own clear removes only light-route.
- test/: deterministic Node model tests; not a replacement for browser gameplay QA.
- tools/: loopback preview and static checks; .github/: pinned Pages deployment.

Shared-summary validation is all-or-nothing (D13, user-approved 2026-10-13). The root has exactly version/apps; apps is an object containing only the existing 15 IDs; every entry has exactly completed/total/updatedAt and must satisfy the existing bounds/date contract. Unknown root/app/entry fields, malformed JSON, wrong types, invalid entries, empty/whitespace-only raw strings or oversize payloads block both report and own-entry clear before any write/delete. Preserve the complete original raw string, including valid peers; never sanitize or repair shared data. Only a missing key (getItem returns null) starts a new empty summary. A valid apps:{} is allowed. Clearing an already absent own entry preserves the original bytes/absence without a write. Identical serialized reports also need no write. On a valid mutation, retain peer values and property order; JSON container whitespace may be re-encoded. Confirm changed shared writes by exact readback. Confirm private clear only when both own keys read back as absent. A failed summary operation does not undo a successful private save/clear or block gameplay; the existing UI reports that separate failure. Readback is not a multi-tab transaction, disk-durability proof or rollback guarantee after an ambiguous IO failure.

Best/progress are keyed by light-v2 + light-run-v1 + code + stage + practice/limited + independent/assisted. Scores keep the original 1,000 minus 15 per move and 120 per hint (floor 20); undo costs a move and cannot erase hint provenance. Limited budgets are a legally validated solution length plus max(1,floor(length/5)) spare moves; they are not a minimum-move proof. Success on the last permitted action is accepted; an unsolved budget exhaustion stops further actions. Practice has no move budget, but the bounded replay cap requires a fresh attempt at 1,024 inputs.

Initial view performs no writes. When a saved run exists, the player explicitly selects continue or a fresh attempt/set; selecting a code/stage/mode starts that stage afresh and replaces the one resume slot. Recent entries retain code and last chosen stage/mode, not additional replay histories. Legacy light-route-v1 best records (previous 120-record boundary) stay intact/read-only, labeled as hint provenance unknown and excluded from new independent achievements; no migration into new scores. Clear removes both own keys and only own gallery entry, without immediately writing a new session. Storage denial/invalid/oversize/incompatible payloads fail safely; a failed own save cannot publish a gallery achievement.

Device-local game progress is explicitly labeled and removable; no cloud persistence, identities or public ranking. No analytics, external AI APIs, accounts, audio or secrets. Runtime network blocked by CSP connect-src none. Browser-origin shared storage is not a backend or official competition proof. No provisioning, account access or deployment changes in this task.
